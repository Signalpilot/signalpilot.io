Your Indicators Are Lying to You (The Repaint Problem)

Reading time ~12 min • Indicator Truth & Detection •

9:38 AM. Your indicator prints a BUY arrow at 5,186. You take it.

By the time that bar closes, the arrow is at 5,179 — seven points lower, sitting exactly where the move actually began. Your fill is still 5,186. The chart now shows a trade you never took, and it looks like a good one.

The indicator did not lie about the past. It rewrote it. That is repainting: a signal that moves, or vanishes, after the bar it printed on has closed, so the history shows entries that were never available in real time.

Why it survives a backtest

A repainting indicator backtests beautifully, because in the backtest every signal already sits where it should have been. Live, it puts you a few points late on every single trade. A few points is the whole edge.

📈 What the moving actually cost

ES is $50 a point, so the displacement above converts straight into money. This is the number the lesson has been circling and never named.

A third of that day was the indicator moving the entry after he had taken it. Same strategy, same stops, same market: seven, five and four points worse than the chart now claims they were.

Across the ten weeks, 43 of the 47 signals moved or vanished, and the three above average 5.3 points. If the rest were like them, the displacement alone comes to 43 x 5.3 x $50, about $11,400 of the $14,700. It is not a component of the loss. It is most of it.

This is precisely the number a backtest cannot show you, because in a backtest the displacement is zero by construction: every signal already sits where it ended up. Run the two columns yourself on whatever you are using — the signal price while the bar is live, the signal price once it has closed, the gap multiplied by your instrument's point value. That figure is what the tool costs you before the strategy has been judged at all.

Recovery: Jake switched to indicators whose signals do not move, and re-ran the same strategy. What matters is not what he then made — one composite trader's figures prove nothing either way. It is that his live results and his backtest finally described the same system.

Jake's advice: "I lost $14,700 trading ghosts—signals that MOVED after bar close. Test EVERY indicator: screenshot live, compare after bar close. If the backtest has a high win rate and almost no drawdown, that is the tell. NEVER trust, ALWAYS verify."

Part 2: Deterministic Indicators

What "Deterministic" Means (And Why It Matters)

Most repainting is not malice. It is what you get by default: the convenient way to pull a higher-timeframe value in Pine Script peeks at a bar that has not closed, and the convenient way to plot a pivot needs bars that have not printed yet. Both produce a chart that looks right in history and is wrong live, and neither requires anyone to intend it.

💡 What deterministic means in code

These are the four constraints an indicator has to satisfy, and they are what to check for in anything you use, this suite included:

  • No future data: All HTF requests use lookahead_off and [1] offsets
  • Fixed signals: Once a signal prints, it never moves or disappears
  • Confirmed bars only: Signals wait for bar close (no intra-bar magic)
  • Open-source auditable: Code is available for independent review

What the four buy you: the chart in front of you and the chart in six months are the same chart. That is the whole property, and it is checkable rather than promised — the bar-replay walkthrough further down is how you check it.

❌ Repainting Indicator

Backtest: flatters, because every signal already sits where it ended up

Live: worse than the backtest by the displacement, on every trade

Problem: signals change after bar close

What you cannot tell: whether the strategy was any good, because the tool moved the entries before you could judge it

✓ Deterministic Indicator

Backtest: the entries it shows are the entries that were available

Live: the same entries, so the gap is execution rather than the tool

Integrity: signals never change

What you get: a backtest worth arguing with. It may still say the strategy is bad

Expect the honest one to backtest worse. It is not using future data, so it cannot show you entries that were not there. A lower backtest number that survives contact with a live market is worth more than a higher one that does not, and that is the whole of the comparison.

Part 3: Audit Framework

How to Check One

Here's your step-by-step framework for auditing ANY indicator before risking real money:

✅ Indicator Audit Checklist

Before trading ANY indicator:

  1. Visual test: Watch 3-5 signals live, check if they move after bar close
  2. Replay test: Use Bar Replay to compare live vs historical signals
  3. Alert test: Set alerts, track 20+ instances, compare to history
  4. Code audit (if available): Check for request.security() red flags

Pass criteria: ALL tests must show consistent signals.

If ANY test fails → DO NOT USE → Find another indicator

Categories That Commonly Repaint

Here's a list of indicator types and specific indicators that commonly repaint. If you're using any of these, test them immediately:

Indicator Type/Name Why It Repaints How to Detect
Zigzag indicators Recalculates pivots as price moves—"perfect" swing detection in history Check if pivot points move after bar close
Higher timeframe (HTF) pulls without lookahead_off Uses future HTF data not available in real-time Code audit: search for request.security() without lookahead=barmerge.lookahead_off
"AI/ML prediction" indicators Many use intra-bar data or future-peeking to show "predictions" Bar replay test—do predictions appear before or after the move?
Divergence indicators (most) Redraw divergence lines as new bars form Screenshot divergence line, check if angle/position changes
Support/resistance zones (dynamic) Zones adjust to fit recent price action perfectly Alert test—set alerts on zone boundaries, verify they don't move

Red flag: a backtest with a very high win rate and almost no drawdown is far more often a repainting indicator than a real edge. Note what the red flag is not: a low win rate. An honest edge can win a third of its trades and still make money, if the winners are large enough. What should make you suspicious is a curve with no pain in it.

Bar Replay Detection Walkthrough

TradingView's Bar Replay feature is one of the best tools for catching repainting indicators. Here's exactly how to use it:

Step-by-Step Bar Replay Test:

  1. Load your indicator on a chart: Use a liquid instrument (SPY, ES, AAPL) on 5-min or 15-min timeframe
  2. Enter Bar Replay mode: Click the Bar Replay button (looks like a play button with a bar chart)
  3. Rewind to 3 days ago: Gives you enough historical data to test 20-30 signals
  4. Play forward bar-by-bar: Watch for signals to appear during bar formation
  5. Document signal timing: Does the BUY signal appear BEFORE price moves up, or AFTER?
  6. Compare to chart history: Exit replay mode, look at the same time period
  7. Check for discrepancies: Are signals in the same location? Or did they move?

Example Test Results (Bar Replay on a reversal indicator):

Replay Mode (Playing forward bar-by-bar):
10:15 AM: No signal shown
10:30 AM: No signal shown
10:45 AM: Price drops from $520 → $518 → BUY signal appears at $519
11:00 AM: Price rallies to $522 (signal worked!)

Historical Chart View (Same time period):
10:15 AM: BUY signal shown at $520 (signal MOVED!)
Original signal: $519 during replay
Historical signal: $520 in chart view
→ Difference: Signal moved 1 point to "predict" the low perfectly

Verdict: REPAINTING DETECTED
Signal appeared at $519 during live bar formation
Signal moved to $520 in historical chart (appears earlier, better entry)
This is future-peeking—indicator adjusts signals after knowing outcome

Code Audit Deep-Dive: Pine Script Red Flags

If an indicator provides source code (open-source on TradingView), you can audit it for repainting issues. Here are the exact code patterns to look for:

Red Flag #1: request.security() without lookahead_off

// ❌ REPAINTING CODE (uses future HTF data)
htf_close = request.security(syminfo.tickerid, "60", close)

// ✅ NON-REPAINTING CODE (waits for HTF bar to close)
htf_close = request.security(syminfo.tickerid, "60", close, lookahead=barmerge.lookahead_off)

// Even better: add [1] offset to use CONFIRMED HTF bar
htf_close = request.security(syminfo.tickerid, "60", close[1], lookahead=barmerge.lookahead_off)

Red Flag #2: Calculations using current bar data without barstate.isconfirmed

// ❌ REPAINTING CODE (signal can change during bar)
signal = close > ema_20 and rsi > 50
plotshape(signal, style=shape.triangleup, color=color.green)

// ✅ NON-REPAINTING CODE (only plots on confirmed bar close)
signal = close > ema_20 and rsi > 50
plotshape(barstate.isconfirmed and signal, style=shape.triangleup, color=color.green)

Red Flag #3: Pivot calculations that recalculate

// ❌ REPAINTING CODE (pivot location changes as new bars form)
pivot_high = ta.pivothigh(high, 5, 5)  // looks back 5 bars, forward 5 bars
// Problem: needs 5 FUTURE bars to confirm pivot → repaints by definition

// ✅ BETTER APPROACH (use fixed swing detection with confirmed bars)
// Signal Pilot approach: detect swing only after 5 bars have CLOSED
// No forward-looking, signals are delayed but honest

Pro tip: If you can't read Pine Script code, use the visual and replay tests instead. Between them they catch the two things that matter — a signal that moves and a signal that vanishes — without needing to read anything. But if you CAN read code, this is the fastest detection method—spot repainting in 30 seconds by searching for these patterns.

Where Signal Pilot sits in this: every indicator in the suite is built to be deterministic — a signal printed on a closed bar stays where it printed. That is a design constraint, not a feature claim, and it is the thing you should verify yourself using the bar-replay walkthrough above rather than take on trust. Run the check on any tool before you let it near a live decision, ours included.

🎓 Key Takeaways

  • Repainting is common in the public library — test everything before trading it
  • Repainting = fake edge — Perfect backtests, disastrous live results
  • Use 4 detection methods — Visual, Replay, Alert, Code audit
  • Deterministic code matters — A signal printed on a closed bar cannot move
  • Which categories to suspect first — zigzags, dynamic zones, most divergence tools, and anything pulling a higher timeframe: each repaints for a different reason, and each has its own test
  • Audit before you trade — 2 hours testing saves months of losses
